# Case Study: The Disappearing Code Mystery [Case study written by AI the developer Arnab is traumatized]

## Background
On September 17, 2026, the `raw://ai-logs/` page was working perfectly, successfully fetching and displaying AI logs. Two days later, on September 19, the UI began throwing a fatal IPC error: `Error: No handler registered for 'get-ai-logs'`. 

The developer clearly remembered writing the IPC handler in `main.js` and securely reading the logs via Electron's `safeStorage`. However, inspecting the active codebase revealed absolutely no trace of `get-ai-logs`, `clear-ai-logs`, or the `safeStorage` decryption logic in the backend. 

The front-end code (`preload.js` and `AILogs/index.html`) remained perfectly intact, creating a baffling "gaslighting" effect where the UI was attempting to call a backend function that apparently never existed.

## Investigation
Initial `git log` and `grep` searches across the active repository yielded no results for the missing backend code. The only commit related to the feature was `"Added Fix for finger print"`, which introduced the HTML/CSS/JS for the frontend and added the `getAiLogs` bridge to `preload.js`, but omitted the backend implementation.

A deeper forensic analysis using Git's hidden reflog (`git log -S "get-ai-logs" --walk-reflogs -p`) uncovered the truth.

## The Sequence of Events (Root Cause)
The disappearance was caused by a devastating sequence of Git commands:

1. **The Code Was Written & Committed:** The developer wrote the flawless backend implementation in `main.js` and committed it locally.
2. **The Frontend Was Committed Separately:** The UI (`index.html` and `preload.js`) was committed in a separate, older commit (`"Added Fix for finger print"`).
3. **The Fatal Command:** While working on the VPN/Wireguard integration on the `RAW-MVP-Wireguard` branch, the developer made a commit (`712ac58: "Added VLSS_REALITY"`). Shortly after, they executed:
   `git reset --hard HEAD~1`
4. **The Erasure:** `git reset --hard` forces the current branch to rewind time by one commit, permanently erasing any unpushed commits or uncommitted working directory changes. The commit containing the `main.js` IPC handlers was caught in the blast radius and orphaned into Git's unreachable reflog. 
5. **The Aftermath:** Because the frontend UI was safely stored in an older commit that occurred *before* the reset point, it survived the wipe. This left the application in a broken, half-implemented state where the UI called backend functions that Git had erased. Along with the AI logs, this single reset command also orphaned the `get-crash-logs`, `clear-crash-logs`, and `get-health-stats` backend handlers.

## Resolution
1. The missing AI backend handlers (`get-ai-logs` and `clear-ai-logs`) were recreated in `src/App/store.js`.
2. The missing Crash Logs and Health Stats handlers (`get-crash-logs`, `clear-crash-logs`, `get-health-stats`) were also completely restored to `src/App/store.js`.
3. The `safeStorage.decryptString` logic was successfully re-implemented to safely read both the encrypted `AI_Res_Log.txt` and `Privacy_Errors_Log.txt` files generated by `logger.js`.
4. The developer's sanity was restored.

## Takeaways
* `git reset --hard` is ruthless and will not ask for confirmation before permanently destroying unpushed commits and uncommitted changes. 
* When code seemingly vanishes but UI remains, checking `git reflog` is the ultimate source of truth to prove whether the code was actually written and subsequently lost due to a branch reset.
